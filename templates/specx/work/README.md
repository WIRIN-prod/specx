# Work continuity

Keep the checkpoint concise and current. Record lifecycle stage; approved blueprint/readiness and roadmap revisions; current component, feature, milestone, or task; completed/in-progress task IDs; branch/base/commit/PR; checks/evidence; research sources and unresolved decisions; blockers; next safe action; and last update. Do not claim completion without evidence. Resume by reading the checkpoint and verifying repository and Git state. Preserve scope and approvals across sessions; do not infer approval from checkpoint status alone.
