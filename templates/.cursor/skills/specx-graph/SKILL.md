# specX graph — linked markdown (agents + Obsidian)

**Read first:** `specx/GRAPH.md` and `specx/Home.md`.

The graph is **authored in markdown**, not generated by CLI. Specialists create links; Critics verify them; approve updates `status` in frontmatter.

## When to use this skill

- Every **specx-specialist** pass (discovery, foundation, feature)
- **specx-propose** — create leaf + link from 07/08/[[Home]]
- **specx-discover** maintenance — add addendum links, do not orphan PRD items
- Before **specx-build** — read active feature via backlinks from [[Home]]

## Specialist checklist (append to every artifact)

1. **Frontmatter** — `specx.layer`, `specx.status`, `specx.phase` or `specx.feature` as appropriate
2. **Body** — wikilink every reference to another artifact (phases, personas, features, specs)
3. **`## Graph` table** — Hub, Upstream (approved only), Downstream, Related (see GRAPH.md)
4. **`[[Home]]`** — update Discovery status row and/or Features list when phase approved or feature created
5. **Phase 07–08** — each feature name → `[[segment/.../leaf/FEATURE]]`; PRD IDs link to leaves or `[[specs/.../spec]]`

## Link conventions

```markdown
[[discovery/08-prd#FR-012]]
[[foundation/STEERING#Non-negotiables]]
[[auth/email/registration/spec]]
[[auth/email/registration/FEATURE|Email registration]]
```

Use aliases after `|` for readable prose. Link living specs under `specs/`; feature deltas under `<leaf>/specs/`.

## Critic graph pass

Add to critique under **## Graph integrity**:

- [ ] `## Graph` section present
- [ ] Upstream links only to **approved** phases (check frontmatter `status: approved`)
- [ ] No dead wikilinks (file exists or stub FEATURE at path)
- [ ] PRD / 07 features link to leaves or explicit UNCERTAIN stub path
- [ ] [[Home]] would list this artifact correctly

## After human approve

1. Set `specx.status: approved` in phase/artifact frontmatter
2. Update [[Home]] table row to `approved`
3. Commit with discovery/foundation/feature files together

## For implementers (build)

Before coding, traverse:

`[[Home]]` → active `[[.../FEATURE]]` → `[[.../spec]]` → `[[.../design]]` → `[[foundation/STEERING]]` → linked discovery phases

Treat the graph as the **navigation layer** over the repo; `specx build` prints paths but does not replace links.
