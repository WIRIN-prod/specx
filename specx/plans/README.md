# Delivery roadmaps and work plans

Store one roadmap per goal, based on an approved blueprint revision whose readiness has been assessed with the user. Organize work by product/architecture milestones, delivery phases, and small implementation tasks. Link milestones and tasks to approved requirement/specification IDs, component dependencies, decisions, acceptance criteria, verification evidence, risk, and suggested model capability with rationale.

Specification approval and roadmap approval are separate. A roadmap is executable only after explicit approval of its exact revision. A task is executable only when its dependencies and required decisions are ready and it is within the approved roadmap scope. Proposed capability/fit is advice, not automatic assignment authority. Preserve history and completed work; changed goals, acceptance conditions, scope, dependencies, or decisions require a revised roadmap and renewed approval.

Use [PLAN-TEMPLATE.md](PLAN-TEMPLATE.md). A suggested capability and fit score are recommendations, not delegated authority. Base them on task risk, ambiguity, architectural impact, scope size, and required judgment; explain the score so the user can revise it.
