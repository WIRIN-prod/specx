# Knowledge proposals

Proposals are review artifacts, not accepted project knowledge. Keep them in this directory with stable IDs and revisions. A proposal must enumerate exact hierarchical specification/component/feature/requirement/decision changes; cite evidence and research sources; distinguish observed current behavior from intended target behavior and migration; list coverage, readiness, unresolved decisions, and roadmap impact; and offer options without selecting for the user.

After explicit approval, record who/when/what was approved in `specx/knowledge/decisions/README.md`, then update the canonical knowledge files. Approval applies only to the exact reviewed proposal revision. Any material change requires renewed approval.
